Pemakaian token

Rincian

Input sudah termasuk token cached. Cached = dibaca dari cache provider (lebih murah). Request stream tanpa laporan usage tetap dihitung, tanpa token.

Provider

URL dan API key diatur di sini, lokal maupun lewat tunnel. Model langsung diambil setelah provider atau key ditambahkan.

Belum ada provider. Tambahkan satu, lalu modelnya muncul di pemilih model chat dengan prefix-nya, misalnya 9r/gpt-4.1.

Keamanan tunnel

Cara rotasi pintar memilih akun

  • Istirahat otomatis. Akun yang kena 429 istirahat sesuai Retry-After (atau 5, 10, 20 detik, dst.), key ditolak 30 menit, kuota habis 1 jam, error server berulang sebentar. Request langsung pindah ke akun lain.
  • Bobot ikut kesehatan. Porsi tiap akun mengikuti bobotmu × tingkat sukses terbaru × kecepatan dibanding akun lain ÷ jumlah request yang sedang jalan.
  • Sesi menempel. Satu chat tetap di akun yang sama selama akun itu sehat, karena cache prompt tersimpan per akun. Inilah yang menaikkan token cached. Chat lain tetap tersebar.
  • Merata, tidak beruntun. Smooth weighted round robin: akun berbobot besar lebih sering dipilih tanpa dipilih berkali-kali berturut-turut.
